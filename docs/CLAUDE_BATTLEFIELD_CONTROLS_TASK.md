## Поведение Deck / Discard

- Верхний/opponent: красные ассеты. Нижний/player: синие.
- При `count > 0` показывать соответствующий production-арт.
- При `count === 0` скрывать foreground-арт, оставляя нарисованное на арене гнездо, label и счётчик `0`. Не изобретать отдельную пустую CSS-карту.
- Число всегда живое и берётся из текущего состояния матча. Оно не должно быть частью изображения.
- Deck использует горизонтальный plaque, Discard — вертикальный. Текст оптически центрировать в внутренней безопасной зоне соответствующего арта.
- Удалить прежние декоративные CSS-слои: стопки из `border`, градиентов, псевдоэлементов, квадратов и круглые badge-счётчики. Допустим только прозрачный layout/hitbox и HTML-текст поверх production-арта.
- Изображения должны сохранять aspect ratio, не растягиваться и не кропаться.
- Посадку измерить относительно реальных painted-slots арены. Если нужен наклон/scale, art и связанный hitbox должны получать одну и ту же transform-chain через общие CSS custom properties. Не подбирать отдельные независимые transform на глаз.

## Поведение Resonance

- Канонический Resonance — горизонтальная панель с пятью гнёздами. Блок с круглыми линзами из старого reference относился к состояниям End Turn, не к Resonance.
- Значение нормализовать/ограничить диапазоном `0..5`.
- Заполнение строго слева направо:
  - `0/5`: все гнёзда пусты;
  - `1/5`: ruby;
  - `2/5`: + topaz;
  - `3/5`: + amethyst;
  - `4/5`: + cyan;
  - `5/5`: + sapphire.
- Монтировать только активные камни. Не делать цветные CSS-кружки, gradients или SVG-замены.
- `РЕЗОНАНС` и значение `N/5` остаются живым HTML-текстом. Разместить значение в правом тёмном отсеке; заголовок — в предусмотренной композицией безопасной зоне, без перекрытия камней.
- Frame и gems — декоративные: `pointer-events: none`, `aria-hidden="true"`. Семантическое значение дать контейнеру через понятный `aria-label`.

## Responsive и границы задачи

- Production-art pass применяется только при `min-width: 1024px`, как уже принято для desktop End Turn.
- На `1023px` и ниже сохранить текущую mobile-композицию и размеры. Новые desktop PNG не должны монтироваться и не должны запрашиваться сетью.
- Не менять `MatchBoard`-геометрию, карточные слоты, руку, аватары, navbar, End Turn или правила игры.
- Не создавать новые изображения. Если приложенный файл недоступен — остановиться и сообщить, а не делать fallback из CSS/SVG.
- Не проводить unrelated refactor и не форматировать несвязанные файлы.

## Состояния и качество взаимодействия

- Частые изменения счётчиков/Resonance: короткий restrained transition без layout shift; уважать `prefers-reduced-motion`.
- Art не должен перехватывать мышь/тач.
- Не допускать CLS при первом рендере: размеры/aspect-ratio известны заранее.
- Не допускать горизонтального скролла и выхода декора за безопасные границы арены.

## Обязательная проверка

1. Lint, typecheck/build и все существующие unit-тесты.
2. Реальный Playwright на desktop: `1366×650`, `1600×720`, `1920×1080`.
3. Регрессия mobile: `390×844`, `430×932`.
4. Чистая граница: `1023px` — mobile/no requests; `1024px` — desktop/art requests.
5. Состояния:
   - red/blue Deck при `0`, `1`, `25+`;
   - red/blue Discard при `0` и `>0`;
   - Resonance `0/5`, `1/5`, `3/5`, `5/5`;
   - `prefers-reduced-motion`.
6. Network: каждый production-файл загружается только когда нужен; на mobile новых запросов нет.
7. Console: без новых ошибок/предупреждений.
8. Проверить, что старые CSS/SVG-имитации Deck/Discard/Resonance удалены и production PNG действительно используются.
